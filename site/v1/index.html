Overview

topopt is a tool for 3D topology optimization. You give it the space that the part can fill, the places that stay fixed, and the loads. It removes the material that does little work. It writes a smooth STL file that you can print.

  • Runs on your computerEverything runs on your computer. The dashboard works with no internet. The first start downloads Python 3.12 and about 200 MB of packages.
  • macOS and LinuxmacOS on Apple silicon (the target) and Linux x86_64. Python 3.12. An Intel Mac is best effort. Windows is not supported. The hook example needs at least 16 GB of memory.
  • Agent or command lineAn MCP server with 27 tools, which an agent client starts. Or the command line: topopt check and topopt run <file.yaml> --out <dir>.
  • Live dashboardIt shows the 3D shape while it forms, the log, and a bar with the pass, the time, the volume and the compliance. It also replays a recorded run.
  • Checks after the runA print report in metrics.json and the command topopt printcheck. With an optional extra, a stress check of the finished STL (topopt verify).

How it works, in 3 steps

  1. Describe the problem

    A YAML file names one STL file for each region: the design space, the fixed regions, the load regions (each with a force vector) and, if you want, keep-out regions. It also sets the material, the volume fraction, the voxel size and the number of passes.

    Or describe the part in words. The skill part-to-topopt writes the YAML and the region files.

  2. Run it and watch

    topopt run starts the run. With --dashboard, the browser shows the 3D shape while it forms. In an agent client, Claude starts the run with the MCP tool run_topopt.

    The hook example takes about 2.5 minutes on an M1 Mac (148 s).

  3. Get a part that you can print

    The result folder holds final.stl (a smooth mesh) and metrics.json. The metrics give the mass, the stiffness of each load case and a print report: overhang, plate contact, support estimate, bed fit and the thinnest member.

The commands of the three steps:

topopt check examples/hook/hook.yaml
topopt run examples/hook/hook.yaml --out runs/hook --dashboard
# the result: runs/hook/result/final.stl and metrics.json

Install

The recommended route is the Claude Code plugin. The other five clients use the same MCP server. Each block has the short steps, the way to update and the way to reinstall. The full steps are in the README and in docs/clients.md.

All clients need uv. It is the only prerequisite. It gets Python 3.12 by itself. Install it with curl -LsSf https://astral.sh/uv/install.sh | sh, or with brew install uv on a Mac. On a Mac, the fast solver needs clang from the Xcode Command Line Tools (xcode-select --install). Without it, topopt uses the slower AMG solver.

Claude Code (plugin)

Recommended
  1. Install uv (see above).
  2. Add the marketplace and install the plugin. Run these two commands in a terminal. 
    claude plugin marketplace add chartergroup/topopt-demo#v0.1.0
claude plugin install topopt@topopt-demo
    The part #v0.1.0 pins the install to the release v0.1.0.
  3. Start claude in a work folder and type /topopt:start-here. Claude checks the machine, helps you describe the part, checks the problem, starts the run, and gives you the dashboard link.
  4. Open the dashboard link (usually http://127.0.0.1:8765/) in a browser to see the shape form.

First start: 1 to 3 minutes. The plugin makes its own Python environment. Claude Code waits only 30 s for an MCP server, so topopt shows failed at first. The setup goes on in the background. When it is done, type /mcp and reconnect topopt.

Update and reinstall

Update. The install names a release tag, so it stays on that release. claude plugin update topopt@topopt-demo alone does not move a pinned install to a new tag. Remove the marketplace, add it with the new tag, and install again. Write the new tag in place of <new-tag>.

claude plugin marketplace remove topopt-demo
claude plugin marketplace add chartergroup/topopt-demo#<new-tag>
claude plugin install topopt@topopt-demo

Reinstall. Run the same three commands with the tag that you have now. marketplace remove also uninstalls the plugin and deletes the plugin data folder. That folder holds the Python environment, so the next start sets up Python again (1 to 3 minutes). A second route keeps the environment. The README has it, in the section Update to a newer release.

Claude Desktop (extension and plugin upload)

You build the extension file from a checkout. The target is a Mac with Apple silicon. The app needs a sign-in to claude.ai. An organization can turn extensions off.

  1. Install uv (brew install uv). The extension starts the server with uv run.
  2. Clone the repo and build the extension file in the checkout. 
    git clone https://github.com/chartergroup/topopt-demo
cd topopt-demo
uv run --no-project --python 3.12 packaging/mcpb/build.py
    It writes dist/mcpb/topopt-<version>.mcpb (about 1.8 MB).
  3. Open the .mcpb file with Claude Desktop, or go to Settings, Extensions and drag the file in. The optional field Work folder is where runs go (empty means ~/Documents/topopt).
  4. First start: 1 to 3 minutes while uv downloads Python and the packages. If the extension shows an error at first, wait for the download. Then turn the extension off and on.
  5. Optional, on a Mac: build the fast solver library. Ask Claude to call environment. It gives the command.
  6. Optional: upload the plugin zip under Customize, Plugins. It adds the skills start-here and part-to-topopt. The README has the command that makes the zip.
  7. Test: ask Claude for the tools of topopt. Then ask it to call team_guide with no role.
Update and reinstall

A Claude Desktop update of the extension replaces the extension folder and removes the solver library on a Mac. Run the build command for the library again then. A change of the Work folder needs a full quit of Claude (Cmd+Q on a Mac).

The full steps are in the README, section Quick start: Claude Desktop.

Cursor

  1. Install uv (see above).
  2. Clone the repo: git clone https://github.com/chartergroup/topopt-demo. The file .cursor/mcp.json is in it.
  3. Optional (the docs advise it): run sh scripts/topopt-env.sh sync in the clone. It makes the Python environment and waits until it is ready. A cold first start takes 1 minute or more, and a client can stop waiting before it ends.
  4. Open the folder in Cursor. Approve the project server if Cursor asks. Under Customize, MCPs, topopt shows with its tools.
Update and reinstall

Update. Run git pull --ff-only in the clone. The environment follows the lock file by itself: the next start installs again when the lock file changed. sh scripts/topopt-env.sh sync does the same in a terminal.

Reinstall. The environment is in the folder .plugin-env/ of the clone. A setup that was cut is repaired by the next start. sh scripts/topopt-env.sh doctor shows the state and changes nothing.

Codex CLI

  1. Install uv (see above).
  2. Clone the repo: git clone https://github.com/chartergroup/topopt-demo. The file .codex/config.toml is in it.
  3. Start codex in the repo root. The relative path in the config needs this. Trust the project when Codex asks. Without trust, Codex ignores the config file.
  4. Type /mcp, or run codex mcp list. topopt shows in the list. After a cold start, the first turn can miss the tools. Ask again, or start Codex again.

VS Code (agent mode)

The config file is not in the repo: you make it from a snippet.

  1. Install uv (see above).
  2. Clone the repo, open the folder in VS Code, and trust the workspace.
  3. Make the file .vscode/mcp.json: 
    {
  "servers": {
    "topopt": {
      "type": "stdio",
      "command": "sh",
      "args": ["${workspaceFolder}/scripts/topopt-env.sh", "mcp"],
      "env": { "TOPOPT_WORKSPACE": "${workspaceFolder}" }
    }
  }
}
  4. Run MCP: List Servers from the Command Palette. Select topopt and start the server.
  5. Open chat in agent mode and ask for the topopt tools.
Update and reinstall

Update. Run git pull --ff-only in the clone. The environment follows the lock file by itself. sh scripts/topopt-env.sh sync does the same in a terminal.

Reinstall. The environment is in the folder .plugin-env/ of the clone. A setup that was cut is repaired by the next start. MCP: List Servers has Restart Server for the server.

The repo also has a root .mcp.json that VS Code reads. With your snippet, VS Code can show two servers named topopt. The page docs/clients.md tells the options.

Gemini CLI

The config file is not in the repo: you make it from a snippet.

  1. Install uv (see above).
  2. Clone the repo and go in.
  3. Make the file .gemini/settings.json: 
    {
  "mcpServers": {

  4. Start gemini in the repo root. The relative path in the snippet needs this. Trust the folder if Gemini asks.

Skills and roles

The repo has two skills and four roles. The skills are in the Claude Code plugin. Codex CLI, Gemini CLI, Cursor and VS Code read copies of them from .agents/skills/. A client without sub-agents gets the four role texts from the MCP tool team_guide. The same texts are MCP prompts.

start-here

Checks that the topopt server and the machine are ready. Then it takes you from a part (in words, or as STL and YAML files) to a printable STL: check, run, dashboard and result. In Claude Code, type /topopt:start-here.

Source: skills/start-here/

part-to-topopt

Turns a plain description of a part (for example a wall hook for a T-shirt, or a bracket for a shelf) into a valid problem YAML and region STL files. It checks them and prints the assumptions. For a part that already has STL files, it is not the skill to use.

Source: .claude/skills/part-to-topopt/

The four roles

Lead design engineer

Finds out the goal, the loads, the mounting, the material, the size and the print limits. States the assumptions. Reviews the final result.

CAD engineer

Turns the brief into the design space, the fixed regions, the load regions and the keep-outs. Looks at the result at the end: shape, fit and details.

FEA engineer

Sets up the loads and the supports in the problem YAML, checks the setup, starts the run, and reads the numbers: compliance, stiffness, lost force, time and memory.

Print engineer

Checks if the result can be printed: fit on the bed, thin members, holes, overhangs, orientation and supports. Gives findings with places and suggestions.

Source: the files in agents/ (the role sub-agents of the plugin) and topopt_mcp/roles/ (the MCP prompts).
