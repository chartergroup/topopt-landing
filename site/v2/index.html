3D topology optimization

Make a 3D part lighter and keep it stiff.

Give topopt the loads and the places that must stay, and it writes a smooth STL file that you can print.

How it works

  1. Describe the part

    A YAML file names one STL file for each region and the force on each load. Or describe the part in words: the skill part-to-topopt writes the files.

  2. Run and watch

    A live dashboard in the browser shows the shape while it forms. An agent client can start the run through the MCP server.

  3. Print the result

    The result folder has a smooth final.stl. The file metrics.json gives the mass, the stiffness and a print report.

topopt run examples/hook/hook.yaml --out runs/hook --dashboard

Install

The recommended route is the Claude Code plugin. All clients use the same MCP server and need uv.

curl -LsSf https://astral.sh/uv/install.sh | sh

  • Claude Code Recommended

    claude plugin marketplace add chartergroup/topopt-demo#v0.1.0
claude plugin install topopt@topopt-demo

    Then start claude and type /topopt:start-here. The first start takes 1 to 3 minutes. Full steps

  • Claude Desktop

    uv run --no-project --python 3.12 packaging/mcpb/build.py

    Run it in a clone of the repo. It builds an extension file. Open that file with Claude Desktop. Full steps

  • Cursor

    git clone https://github.com/chartergroup/topopt-demo

    The clone has the file .cursor/mcp.json. Open the folder in Cursor. Full steps

  • Codex CLI

    git clone https://github.com/chartergroup/topopt-demo

    The clone has the file .codex/config.toml. Start codex in the repo root. Full steps

  • VS Code

    git clone https://github.com/chartergroup/topopt-demo

    Make the file .vscode/mcp.json from the snippet in the docs. Then use agent mode. Full steps

  • Gemini CLI

    git clone https://github.com/chartergroup/topopt-demo

    Make the file .gemini/settings.json from the snippet in the docs. Start gemini in the repo root. Full steps

Skills and roles

Two skills

start-here
Checks the machine, then takes you from a part to a printable STL. Source
part-to-topopt
Turns a plain description of a part into a problem YAML and region STL files. Source

Four roles

Lead design engineer
Finds the goal, the loads and the print limits. Reviews the result.
CAD engineer
Makes the design space, the fixed regions, the load regions and the keep-outs.
FEA engineer
Sets the loads and the supports, starts the run and reads the numbers.
Print engineer
Checks fit on the bed, thin members, overhangs and supports.

A client without sub-agents gets the role texts from the MCP tool team_guide.
